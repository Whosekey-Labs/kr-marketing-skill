# 8. 운영 루프 (상시): 리뷰 · 재방문 · 프로모션 · 연간 달력

목표: 콘텐츠 생산과 별도로 늘 돌리는 일. 로컬 가게는 리뷰와 재방문이 콘텐츠보다 먼저 성과로 이어지는 경우가 많다. 대화가 열릴 때 밀린 일 점검(`guides/04-weekly.md` ⓪)에서 이 파일의 해당 칸만 확인한다.
이 파일은 방문형 가게 기준이다. 매장 없는 사업(온라인·외주·B2B)은 '리뷰 운영'을 크몽 등 플랫폼 후기·홈페이지 문의 응대로 바꿔 읽고, 플레이스·매장 안 항목은 건너뛴다.

## 1) 리뷰 운영

### 확인 주기
예약 실행 기능이 있으면 이틀에 한 번, 없으면 대화가 열릴 때마다(`guides/04-weekly.md` ⓪) 새 리뷰를 본다(연결·브라우저로 직접, 안 되면 사장님이 캡처). 부정 리뷰는 본 그날 답글 초안을 내고, 그 외는 영업일 1~2일 안에 낸다.

### 세 갈래로 나눈다

| 갈래 | 예 | 할 일 |
|---|---|---|
| 허위·욕설·개인정보·반복 게시 | 방문 안 한 사람의 글, 욕설, 직원 실명 | 신고: 스마트플레이스 → 권리침해 신고 → 권리보호센터. 리뷰 쓴 사람에게 따로 연락해 삭제를 요청하지 않는다 |
| 맛·양·서비스 불만 | "짜요", "느려요" | 공개 답글: 공감 → 사실 확인(단정하지 않기) → 조치. 공개 답글은 두 번까지, 그 뒤는 비공개 채널로 |
| 위생·안전 | 이물, 식중독 의심, 다침 | **마케팅으로 다루지 않는다.** 증빙 보관, 필요한 행정 보고가 먼저(식품 이물은 영업자 보고 의무가 있다). 확인된 사실만 짧게 공지. 사장님께 즉시 알린다 |

- 맛·양 같은 주관적 평가는 신고로 내리기 어렵다. 답글로 대응한다.
- 답글은 리뷰 1개에 1개다. 욕설·비꼼·손님 개인정보 추정 금지.
- 칭찬 리뷰 답글은 손님이 쓴 말을 받아 짧게, 복붙 문구 반복 금지. 가게 사실과 말투(프로필)를 반영한다.
- 논란이 커지면(지역 커뮤니티 확산 등) 사과문 **초안까지만** 쓰고 게시는 사장님이 정한다. 법적 분쟁 소지가 보이면 전문가 상담을 권한다.
- "리뷰 삭제 대행", "좋은 리뷰로 덮기" 업체는 쓰지 않는다.

### 리뷰 요청·리뷰 이벤트 (플랫폼별)

| 플랫폼 | 리뷰 대가 이벤트 | 조건 |
|---|---|---|
| 네이버 플레이스 | 플랫폼상 조건부 허용 — **이 스킬은 기본 제안하지 않음** | 실제 결제 영수증만 / 점수·표현 요구 금지 / 작성 화면 확인·대신 작성 금지 / 이벤트용 저가 영수증 금지 / 대행사·리워드 앱 금지 / 손님에게 "대가 받은 리뷰" 표시 안내 |
| 구글 비즈니스 프로필 | 금지 | 대가 제공, 만족한 손님에게만 골라 요청하기 모두 금지 |
| 병의원·의료로 오인될 수 있는 업종(모든 플랫폼) | **하지 않음** | 체험단·이벤트 후기는 치료경험담이라 광고 표시를 해도 의료법상 금지(보건복지부 의료광고 가이드라인 Q2). 대가 제공이 환자 유인인지는 사안별 판단(대법원 2010도1763) — `guides/compliance/medical.md` |
| 배달앱 | 확인 필요 | 각 앱 약관 확인 전에는 하지 않는다 |

- 네이버는 금지 행위가 **단 한 번만 확인돼도 가게 단위 제재**(업체 리뷰 전체 미노출, AI 브리핑 삭제)를 할 수 있다(네이버 공지 957, 2026-01).
- **대가를 주는 리뷰 이벤트는 기본으로 제안하지 않는다.** 조건을 지켰는지 증명할 책임이 가게에 있고, 직원이 "별 5개 부탁드려요" 한마디만 해도 위반이 된다.
- 사장님이 먼저 원하면: ① 허용 조건(실제 결제 영수증, 내용·점수에 관여하지 않기) ② 금지 행위(점수·표현 요구, 작성 화면 확인·대신 작성, 이벤트용 저가 영수증, 대행사·리워드 앱)와 걸렸을 때의 위험을 알리고, ③ 직원 교육 문구("손님께 별점·내용은 절대 말하지 않아요")를 함께 준 뒤, ④ 사장님 확인을 받고서만 만든다. 업종 파일이 금지하면 업종 파일을 따른다.
- **지인·가족 리뷰는 부탁하지 않게 한다**(이용하지 않은 리뷰는 `guides/03-strategy.md` 10)의 하지 않을 것). 사장님이 "지인한테 리뷰 써 달라고 할게요"라고 하면: "실제로 이용한 손님 리뷰만 받는 게 안전해요. 오픈(이용) 뒤 손님께 대가 없이 부탁하는 방법을 드릴게요." 업종 검수표에 더 강한 규칙이 있으면 그것을 따른다.
- 대가 없이 리뷰를 부탁하는 것은 괜찮다. 문구 예: "오늘 어떠셨는지 리뷰로 남겨 주시면 큰 힘이 돼요." (매장 안에서 부탁하는 법은 6))

## 2) 재방문 메시지 (알림받기·쿠폰·카카오)

### 순서 (돈 안 드는 것부터)
네이버 알림받기·쿠폰(무료) → 포스·스탬프 멤버십 → 카카오톡 채널 유료 발송. 카카오는 **친구 수 × 건당 단가**로 월 비용을 먼저 보여 주고, 발송은 월 1~2회로 제한한다.

### 메시지 법규 점검 (정보통신망법 제50조)
쿠폰 발급·소멸 안내도 **광고성 정보**다. 메시지 초안마다 아래를 자동으로 넣고 확인한다.

| 항목 | 기준 |
|---|---|
| 맨 앞 | "(광고)" |
| 보내는 곳 | 가게 이름·연락처 |
| 수신 거부 | 무료로 거부하는 방법 |
| 보내는 시간 | 낮 시간(10~20시 기본). 21시~08시는 별도 동의 없이는 안 됨. 카카오 브랜드 메시지는 08:00~20:50 |
| 동의 | 명시적 사전 동의를 받은 사람만. 동의 문구는 "광고성 정보 수신 동의"를 그대로 쓴다("혜택 알림 받기"만 쓰지 않는다) |

- 기본은 이야기형 소식(신메뉴 굽는 이야기, 계절 소식)이다. 할인은 세 번에 한 번 이하로.
- 손님 연락처 명단은 받지 않는다. 발송은 플랫폼 기능 안에서만 한다.

## 3) 가격·프로모션 설계

프로모션을 제안할 때는 항상 세 가지를 같이 낸다.

1. **목적 1개**: 신규 / 재방문 / 객단가 / 빈 시간대 중 하나
2. **건당 남는 돈 계산**: 판매가 − 원가 − 플랫폼 수수료 − 할인액. 모르는 값은 `[직접 입력]`
3. **끝난 뒤 계획**: 끝나면 무엇으로 손님을 붙잡나

| 문제 | 맞는 제안 | 피할 것 |
|---|---|---|
| 건수(손님 수) 감소 | 신규 유입 제안, 기간·대상 한정 할인 | 기본 메뉴 상시 할인 |
| 객단가 감소 | 세트·추가 메뉴, 증정(덤) | 전체 할인(객단가가 더 내려간다) |
| 재방문 부족 | 다음 방문 쿠폰, 첫 방문 혜택을 다음 몇 번에 나눠 주기 | 첫 방문 큰 할인 한 번 |

- 기본값은 **증정·세트·다음 방문 쿠폰**. 전체 금액 할인은 기간 한정·대상 한정일 때만.
- 배달앱 할인은 할인액에도 수수료가 붙을 수 있다. 현행 요율을 확인하고 계산한다.
- 병의원 할인·이벤트 광고는 의료 규제 플래그 검수표를 먼저 본다.

## 4) 연간 이벤트 달력

1. 네 겹으로 쌓는다: ① 공휴일·대체공휴일·복날(한국천문연구원 월력요항) ② 지역 축제·학사일정(지자체 공지) ③ 정책 이벤트(소비쿠폰 등) ④ 업종 대목(업종 파일) + 가게 휴무.
2. 이벤트마다 "우리 가게에 +인지 −인지"를 적는다. 지난해 포스 기록으로 확인하고, 없으면 "가정"으로 표시한다. (예: 대학가는 방학에 손님이 줄 수 있다.)
3. 홍보는 **D-14~21**부터 예열한다. 연휴 영업시간은 미리 플레이스에 넣자고 제안한다.
4. 시즌이 바뀌면 플레이스 대표 사진·소개글 키워드 교체를 제안한다.
5. 매년 7월쯤 다음 해 달력을 갱신한다(월력요항은 매년 6월 말 발표).
6. 검색 추이는 `mk.py trend`(데이터랩 키가 있으면 데이터랩) 또는 사장님이 보낸 데이터랩 화면 캡처로 "언제 오르기 시작하나"만 본다. 값은 상대값이라 양 비교에 쓰지 않는다.

## 5) 이상 신호

| 신호 | 먼저 할 일 |
|---|---|
| 같은 불만이 반복 | 콘텐츠보다 본질 문제로 사장님께 먼저 알린다 |
| 노출이 갑자기 사라짐 | 제재·정책 공지·지도 핀 위치부터 확인한다. 광고비 증액·할인부터 하지 않는다 |
| 별점 하락 | 최근 낮은 점수 리뷰의 공통 원인을 정리해 알린다 |

## 6) 후기·입소문 만들기 (매장 안 + 손님 게시물 + 초대 체험)

온라인 글만으로는 리뷰·알림받기가 잘 늘지 않는다. 손님을 만나는 자리에서 만든다. 사장님께는 **출력할 파일과 놓을 위치**로 준다.

| 수단 | 할 일 | 지킬 것 |
|---|---|---|
| 계산대 한 마디 | 직원용 문구 1개. 예: "알림받기 해 두시면 새 빵 나오는 날 알려 드려요." | 대가 없이 부탁만. 별점·내용 언급 금지 |
| QR 1개 | 테이블·영수증·계산대에 QR 1개. 이번 달 목표에 맞는 하나만: 재방문이면 알림받기, 신규면 리뷰 | 두 개를 같이 붙이지 않는다 |
| 따라 찍을 자리 1곳 | 손님이 사진 찍기 좋은 자리(창가, 진열대, 간판 앞) 하나를 정하고 작은 안내를 둔다 | 다른 손님 얼굴이 찍히지 않는 자리 |
| 손님 게시물 다시 쓰기 | 우리 가게를 태그한 게시물 중 좋은 것을 주 1개 골라 메시지(DM)로 동의를 받는다 | 동의받은 것만, 정식 기능(리포스트·공동 게시)으로만. 동의 날짜를 기록한다 |
| 초대 체험 (목적지형·신메뉴 출시 때만) | 작은 계정을 초대해 먹어 보게 한다. 팔로워 수보다 저장·댓글 비율과 우리 지역 팔로워 비율을 본다 | 대가 표시 필수, 원고·별점 요구 금지, 한 달 3명 이하. 동네형은 기본으로 하지 않는다. 병의원은 하지 않음(체험 후기 = 치료경험담, `guides/compliance/medical.md`) |

## 7) 지난 이벤트 정리 (대행사 시절 등)

사장님이 지난 리뷰 이벤트(예: "영수증 리뷰 쓰면 무료 혜택", 리워드·체험단)를 말하면, 탓하지 않고 순서대로 안내한다. **위반이라고 단정하지 않는다** — "문제가 될 수 있어요"까지만.
1. **지금도 진행 중인지** 먼저 묻는다(질문 1개). 진행 중이면 오늘 멈추자고 권한다: 매장 안내문·직원 안내·쿠폰 지급을 멈추고, 이벤트 글·공지에 "○월 ○일로 종료" 한 줄을 넣거나 내린다.
2. **과거 글·공지 정리 목록**을 만든다(사장님 블로그·인스타·플레이스 소식·매장 안내문). 내리기·종료 표시·그대로 두기 중 사장님이 고르게 한다. 손님이 쓴 리뷰는 손님 것이라 지우라고 연락하지 않는다.
3. **왜 정리하나**(한 번만, 쉬운 말): "네이버는 리뷰 대가 조건(실제 결제 영수증, 점수·내용 요구 금지, 대행사·리워드 앱 금지 등)을 어긴 게 한 번만 확인돼도 가게 리뷰 전체를 안 보이게 할 수 있다고 공지했어요(네이버 공지 957, 2026-01). 예전 이벤트가 조건에 맞았는지는 저도 단정할 수 없어서, 지금 멈추고 정리해 두는 게 안전해요."
4. **병의원**이면 더한다: "환자 후기를 대가로 받은 이벤트는 의료법상 치료경험담 광고로 볼 수 있고, 혜택 제공이 환자 유인에 해당하는지는 사안마다 달라요. 원장님이 직접 확인해 주세요(필요하면 보건소·의료광고 심의 기관)." 근거는 `guides/compliance/medical.md` 2·6절. 새 리뷰 이벤트는 만들지 않는다(1) 표).
5. 정리한 날짜와 한 일을 프로필 '변경 기록'에 한 줄 남긴다. 이후 리뷰는 대가 없는 부탁(1)·6))으로만 받는다.
