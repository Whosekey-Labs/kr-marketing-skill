# 24. 소프트웨어·IT·SaaS·앱 (AI 자동화 서비스 포함)

SaaS·앱(구독형), 홈페이지 제작, IT 외주 개발, **AI 업무 자동화 서비스**(사무 자동화 대행, 챗봇·업무 도구 구축). 혼자 외주 개발을 하면 `25-solo-brand.md`.
기본 플래그: `common`, `ecommerce`(온라인 결제·구독을 받으면). 핀테크면 `finance`. 문자·카톡을 보내면 `ad-messaging`.
근거 메모: 작은 SW·홈페이지 제작사는 채널이 23 B2B와 거의 같았다(네이버 검색 + 네이버 블로그). 차이는 **콘텐츠(데모·비교 글)**뿐이다(실측 2026-11).

## 1) 이 업종 손님이 우리를 찾는 상황 (JTBD)

손님은 기술이 아니라 **일이 막힌 순간**에서 출발한다. 1단계 조사에서 상담 기록·검색어로 상황 3개를 고른다. (아래는 판단 가설)

| 상황 | 손님 속마음 | 확인하는 것 |
|---|---|---|
| 같은 사무 일을 매일 손으로 반복(엑셀 정리, 주문·예약 옮기기, 보고서) | "이거 자동으로 안 되나, 얼마 들지" | 비슷한 업종의 **전후 사례**, 기간, 비용 범위 |
| 사람 뽑기 어렵고 일은 늘어남 | "사람 대신 AI로 될까" | 실제로 되는 일과 안 되는 일, 데모 |
| "AI 써 보라"는데 우리 일에 어떻게 쓸지 모름 | "우리 같은 작은 가게도 쓸 수 있나" | 쉬운 설명, 작은 회사 사례, 상담 |
| 홈페이지·앱이 필요 | "견적이 업체마다 왜 이렇게 다르지" | 견적 비교 글, 포트폴리오, 진행 절차 |
| 쓰는 도구를 바꾸고 싶음(SaaS) | "옮기기 어렵지 않나, 비용은" | 기능 비교, 가격표, 무료 체험 |

## 2) 맨 앞에 할 일 (첫 단계)

이 업종의 게이트는 **전환·추적**이다(실무 관행: 쇼핑몰은 추적·퍼널, B2B는 타깃 회사·문의 경로부터). 글보다 먼저 한다.

**공통 단계 대신 쓸 질문.** `guides/02-interview.md` 라운드 1(처음·단골 비율, 손님 한 분이 쓰는 돈, 빈 시간)과 `guides/03-strategy.md`의 객단가 공식 대신 `guides/industries/23-b2b.md` 2)의 '### B2B 질문 4개' 절(이 파일만 그 절까지 읽는다)(리드 경로, 영업 주기, 의사결정자, 계약 단가)를 묻는다. 매출은 **노출 × 신청 비율 × 계약 비율 × 계약 금액**으로 나눈다. 구독형(B)은 4번을 "월 구독료와 평균 유지 개월"로 바꿔 묻는다.

1. **타깃 한 문장(ICP)**: 업종·규모·결정자·막힌 일. 예: "직원 5~30명 사무실에서 대표가 직접 결정하는, 매일 반복되는 주문 정리 일".
2. **랜딩 페이지 한 장**: 누구의 → 어떤 일을 → 어떻게 바꾸나 → 실제 사례 → 진행 절차·가격 기준 → 신청 버튼(무료 상담·데모 신청·체험 가입 중 하나). 없으면 블로그 고정 글로 대신한다.
3. **퍼널 정의**: 검색·콘텐츠 노출 → 랜딩 방문 → 신청(상담·데모·체험) → 계약·유료 전환 → 유지·재계약. 단계마다 숫자를 볼 곳을 정한다.
4. **추적 설정 점검**: 랜딩에 분석 도구가 있고 "신청 완료"가 기록되는지, 검색광고를 쓰면 전환이 잡히는지 확인한다. 없으면 신청 폼에 "어디서 보셨어요" 칸을 넣는다.
5. **데모 자산**: 실제 화면 녹화 1~3개. **고객 데이터·이름·전화번호는 가린다.**
6. **가격 공개 방식 정하기**: 정찰가·범위·"상담 후 견적" 중 하나. 구독형은 가격·결제 주기·해지 방법을 한 화면에.
7. 경쟁 3~5곳의 랜딩 구성, 블로그 30일 글 수, 유튜브 구독자를 기록해 3)을 덮어쓴다.

## 3) 채널 등급 가설

| 등급 | 채널 | 할 일 | 근거 |
|---|---|---|---|
| 핵심 | 랜딩 페이지 + 네이버 검색광고 | 신청을 받는 곳 | 실측(2026-11) 수정 순서 1위(소규모) |
| 핵심 | 네이버 블로그(사장님) | 검색어를 노린 사례·비교·사용법 글 | 이목디자인 30일 9건, 언웹스 8건(견적 비교 글), 맛집부킹(소규모 SaaS) 4건(실측 2026-11, 업체 3곳) |
| 확장(시험) | 크몽 등 외주 플랫폼 | 제작·자동화 단품 상품 | 실측(2026-11) 수정 순서 3위, 등록·리뷰 수는 미확인 |
| 확장 | 유튜브 | 데모·사용법 영상 | 소규모는 4위. 성장기 예: 채널톡 9.02만(실측 2026-11) |
| 확장 | 숏폼·카드뉴스 | 블로그·데모를 짧게 바꿔 배포 | B2B·SaaS 숏폼 12편 중 F04 6, F01 2(실측 2026-11, 업종별 숏폼 표본) |
| 확장 | 인스타·카톡 채널 | 고객 소식·문의 | 맛집부킹은 랜딩 + 블로그 + 인스타 + 카톡(실측 2026-11) |
| 제외(기본) | 링크드인 | 소규모에서 근거 없음 | 맛집부킹 유튜브·링크드인 없음. 링크드인은 성장기(채널톡)에서만 확인(실측 2026-11) |

갈래별 차이:
- **A 제작·외주형**: 블로그 사례·견적 비교 ≈ 검색광고 > 크몽 > 유튜브.
- **B 구독형**: 랜딩 + 검색광고 > 블로그(사용법·비교) > 유튜브 데모. 체험→유료 전환을 매주 본다.
- **C 성장기**: 가설 순서(랜딩·검색 > 블로그·사례 > 유튜브 데모 > 링크드인·커뮤니티).

## 5) 사장님에게 받을 소재

처음 한 번:
- [ ] 지난 프로젝트·고객 3~5건: 고객 업종·규모, 전에 하던 방식, 바꾼 뒤, **측정한 숫자와 측정 방법**, 공개 동의 여부
- [ ] 데모 화면 녹화(고객 데이터 가린 것), 서비스 화면 캡처
- [ ] 가격표 또는 견적 기준, 진행 절차, 계약·해지 조건
- [ ] 자주 받는 질문 10개, "이건 안 됩니다" 목록
- [ ] 만든 사람 사진·소개(얼굴이 부담되면 작업 화면·손)
매주: 이번 주 작업 하나의 전후 화면 2장 + 2분 음성 메모(무엇이 막혔고 어떻게 풀었나).

## 8) KPI

| 층 | 지표 | 확인 위치 |
|---|---|---|
| 결과(월) | A: 계약 건수·금액, 상담→계약 비율 / B: 유료 전환 수, 월 반복 매출, 해지 수 | 장부·결제 관리 화면 |
| 행동(주) | 랜딩 방문 → 신청 비율, 신청 수(채널별), 데모 시청, 체험 가입 수, 첫 답까지 걸린 시간 | 분석 도구, 신청 폼, 문의 기록 |
| 실행(주) | 사례·비교 글 수, 데모 영상 수, 측정 근거가 있는 사례 수 | 직접 기록 |

- 결과가 안 나오면 퍼널을 단계별로 쪼갠다: 노출 → 클릭 → 신청 → 계약. 숫자가 빠진 단계부터 고친다(실무 진단 순서). 신청이 적으면 랜딩·사례를, 계약이 적으면 응대·가격을 먼저 본다.
- 검색광고는 신청 1건당 비용으로 본다.

## 9) 하지 않을 것

- 추적 없이 콘텐츠부터 늘리기.
- 측정하지 않은 절감 숫자, "AI가 다 한다" 식 과장.
- 고객 데이터가 보이는 화면 공개.
- 링크드인부터 시작하기(소규모 근거 없음).
- AI 요약 글을 같은 틀로 대량 발행하기(네이버 스팸 정책: 기계적 생성 글 무분별 발행).
- 기술 용어 위주 글. 손님 업무 말로 쓴다("API 연동" → "주문이 들어오면 장부에 저절로 적혀요").
