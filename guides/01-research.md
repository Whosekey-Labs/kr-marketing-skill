# 1. 묻기 전에 스스로 조사

목표: 상호·지역(또는 링크)만으로 검색·지도·리뷰에서 알 수 있는 것을 다 알아낸다. 사장님에게는 결과를 "이렇게 파악했는데 맞나요?"로 확인만 받는다. 조사로 알 수 있는 것은 2단계에서 묻지 않는다.

## 공통 규칙

- 같은 사이트를 연달아 열 때 **1초 이상 간격**을 둔다. 수십 번 몰아서 열지 않는다.
- 로그인·보안문자가 나오면 그 항목은 "확인 못 함"으로 적고 넘어간다. 사장님께 화면을 넘기는 건 꼭 필요할 때만.
- 숫자는 본 그대로 적는다. 못 본 값은 비워 둔다. 짐작해서 채우지 않는다. 조사 날짜를 적는다(리뷰 수·순위는 날마다 바뀐다).

## 1) 가게 찾기 + 네이버 플레이스

| 모드 | 방법 |
|---|---|
| 스크립트 | `python3 mk.py place "망원동 ○○카페"` → 이름·업종·방문자 리뷰 수·블로그 리뷰 수·예약·톡톡 여부·플레이스 ID |
| 브라우저 | `https://m.search.naver.com/search.naver?query={지역+상호}` → 가게 누르기. 상세는 `https://m.place.naver.com/place/{ID}/home`, 리뷰 `…/review/visitor`, 사진 `…/photo`. 메뉴·가격 탭 이름은 업종마다 달라 화면에서 누른다 |

### 못 찾거나 헷갈릴 때 (이 순서로)

| 상황 | 할 일 |
|---|---|
| 사장님이 말한 지역과 자료·링크의 지역이 다름 | 둘 다 검색한다. 확인 메시지에서 하나만 묻는다: "가게 주소가 망원동인가요, 정발산동인가요?" 답 전까지 지역이 필요한 칸(순위·상권·태그)은 빈칸 |
| 같은 이름이 같은 지역에 여럿 | 주소·업종으로 고르고, 그래도 모르면 후보 2~3개를 번호로 보여 주고 고르게 한다 |
| 같은 이름이 **다른 지역**에만 있음 | 우리 가게로 쓰지 않는다. 리뷰·전화·사진을 가져오지 않고 "다른 지역 동명 업체(○○구) — 우리 가게 아님"으로만 적는다 |
| 지역+상호로 못 찾음 | 상호만, 띄어쓰기 바꿔, 영문·한글 바꿔, 대표 메뉴+지역으로 **한 번씩만** 더(모두 4번 안쪽). 그래도 없으면 검색을 그만하고 아래 '확인 메시지'의 못 찾았을 때 문구로 등록 상태를 묻는다(**중간부터 요청이면 묻지 않고** 결과물 뒤 한 줄로, 확인 메시지 맨 아래) |

**못 찾았다 ≠ 등록 안 됨.** 검색에 안 나오는 이유는 여럿이다: 등록된 이름이 다름(띄어쓰기·영문·지점명), 막 등록해 아직 안 뜸, 주소·업종이 다르게 들어감, 누가 대신 만들어 사장님도 모름. 그래서 단정하지 않고 사장님께 세 갈래로 묻는다.

| 사장님 답 | 할 일 |
|---|---|
| 가. 등록돼 있음 | 링크를 받는 법을 안내한다: "네이버 지도 앱에서 가게를 열고 '공유' → '링크 복사'해서 붙여 주세요. 어려우면 지도에 나오는 가게 이름 그대로(띄어쓰기까지)나 주소 한 줄도 돼요." 링크가 오면 플레이스 ID로 다시 조사한다. 끝내 못 받으면 "등록됨·위치 확인 못 함"으로 적고, 첫 결과 1번을 **새로 등록이 아니라** "스마트플레이스에 로그인해 등록된 이름·주소 확인하기"로 한다 |
| 나. 등록 안 함 | "신규·미등록"으로 적고 갈래 ①(상황 4번이면 ④)로 간다. 첫 결과 1번은 플레이스 등록 |
| 다. 모름 | 확인 방법을 짧게 준다: "① 네이버 지도에서 가게 주소를 검색해 건물을 눌러 보세요 ② 스마트플레이스(smartplace.naver.com)에 사장님 네이버 아이디로 들어가 '내 업체'를 보세요 ③ 누가 대신 만들어 줬다면 그분 아이디일 수 있어요." 확인 전까지 첫 결과 1번은 "등록 여부 확인"으로 둔다. **중복 등록이 될 수 있으니 확인 전에는 새로 등록하라고 하지 않는다** |

검색 결과가 가게와 무관한 글(같은 단어가 들어간 다른 가게·상품)뿐이면 "사장님 블로그 없음 / 손님 후기 확인 못 함"으로 적는다. 도구가 붙인 "[손님 후기 추정]" 표시보다 2)의 판별 신호를 따른다.

적을 것:
1. 기본 정보: 주소, 영업시간·휴무, 전화, 업종 표시, 소개글 유무
2. 사진: 대표 사진 첫 장이 무엇인지, 사진 수, 메뉴 사진 유무
3. 메뉴·가격: 등록 여부, 대표 메뉴 3개(가격 포함, 보인 그대로)
4. 기능: 예약, 쿠폰, 톡톡, 알림받기, 주문 — 켜짐/꺼짐
5. 부가정보(주차·노키즈존·단체석 등) 입력 여부 — 사장님이 넣은 것만 노출된다
6. 리뷰: 방문자 리뷰 수, 블로그 리뷰 수, **최근 30일 리뷰 수**, 가장 최근 리뷰 날짜, 답글(최근 리뷰 10개 중 사장님 답글이 달린 수)
7. 별점: 공개 여부와 평균(사업주가 끄고 켤 수 있다. 꺼져 있으면 "비공개"로 적는다)

## 1-1) 매장 없는 사업(⑤)이면: 플레이스 대신 홈페이지·플랫폼

1. 홈페이지가 있으면 HTML을 직접 받아 읽는다(스크립트: 파이썬 `urllib`, 브라우저: 그냥 연다). 적을 것: 첫 화면 한 문장, 서비스·가격 공개 여부, 문의 경로(전화·폼·카톡·메일)와 몇 번 눌러야 닿는지, 고객 사례·후기 유무, 대표색(CSS의 색 값).
2. 크몽·숨고·스마트스토어 같은 플랫폼 상품 페이지: 후기 수, 가격, 판매 수(보이면). 화면이 안 열리면 "확인 못 함".
3. 유튜브는 `https://www.youtube.com/@{핸들}/videos`, 블로그는 2)대로.
4. 플레이스·지역 순위는 보지 않는다. 4) 경쟁은 "그 서비스를 찾는 검색어"와 플랫폼 검색 상위로 본다.

## 2) 블로그 (사장님 글과 손님 후기 나누기)

| 모드 | 방법 |
|---|---|
| 스크립트 | `python3 mk.py search-blog "{지역} {상호}" --name "{상호}"` (`--name`을 주면 사장님 블로그를 표시해 준다) |
| 브라우저 | `https://search.naver.com/search.naver?ssc=tab.blog.all&query={상호}` 상위 30개 |

| 글마다 구분 | 판별 신호 |
|---|---|
| 사장님 글 | 같은 블로그에 가게 이름이 반복, "저희·원장·대표·사장" 화자, 공지·신메뉴·휴무 글 |
| 손님 후기 | "다녀왔어요·내돈내산·맛집" 등 방문기, 블로그 주제가 여러 가게 |
| 협찬·체험단 후기 | "#협찬·제공받아·체험단" 표시, 비슷한 시기에 몰려 올라옴 |

적을 것: 사장님 블로그 주소(있으면), 최근 30일·90일 손님 후기 수, 협찬 후기 비율(대략). 음식점·베이커리·숙박·반려동물은 검색 상위 대부분이 손님 후기다. 이 업종은 사장님 블로그 상태보다 **손님 후기 흐름**이 더 중요하다.

## 3) 인스타그램·유튜브·그 밖의 채널

- 인스타: 플레이스·블로그에 걸린 링크를 먼저 쓴다. 없으면 브라우저로 `https://www.instagram.com/{계정}/`. 로그인 창이 뜨면 "확인 못 함".
- 유튜브: `https://www.youtube.com/results?search_query={상호}` → 채널이 있으면 `https://www.youtube.com/@{핸들}/videos`. 당근·카카오 채널·스마트스토어는 플레이스나 블로그에 링크가 있을 때만 연다.

채널마다: 팔로워(구독자) 수, 마지막 게시일, 최근 30일 게시 수, 최근 10개 중 반응(좋아요·댓글·조회)이 가장 큰 1~2개와 그 주제. 인스타는 로그인 없이 보이는 프로필 첫 화면 12개로만 판단하고, 안 보이는 값은 "확인 못 함"(짐작해 채우지 않는다).
- **온라인 판매 흔적**(스마트스토어·택배·온라인 주문 링크)이 있으면 확인 메시지에 한 줄 넣는다: "택배·온라인으로도 파시나요?" 판다고 하면 업종 파일대로 `ecommerce` 플래그를 켠다.

## 4) 경쟁 3~5곳 (같은 검색어 상위)

경쟁자는 사장님이 생각하는 곳이 아니라 **손님 검색에서 같이 뜨는 곳**이다.

1. 검색어 3~5개를 만든다: `{지역}+{업종}`(예: 망원동 카페), `{지역}+{상황}`(예: 망원동 작업하기 좋은 카페), `{지역}+{대표 메뉴}`.
2. 실행:
   - 스크립트: `python3 mk.py rank "망원동 카페,망원동 크루아상,망원동 작업 카페" --name "{상호}"` (쉼표로 한 번에) → 상위 목록과 우리 가게 순위
   - 브라우저: `https://m.search.naver.com/search.naver?query={검색어}`의 플레이스 목록(1페이지)
3. 여러 검색어에 겹쳐 나온 곳 3~5개를 고른다. 프랜차이즈 대형점보다 **비슷한 규모**를 우선한다.
4. 곳마다 같은 칸으로 적는다: 방문자 리뷰 수, 최근 30일 리뷰 수, 대표 사진 첫 장, 소개글 첫 문장(대표 키워드), 가격대, 인스타·블로그 활동(최근 30일 게시 수), 쿠폰·이벤트, **최근 30일 주제 3개 / 아무도 안 다루는 주제**(빈자리 — 3단계 포지셔닝 재료).
5. **목적지형**(일부러 찾아오는 곳: 리뷰에 "멀리서", "일부러", 다른 동네 이름이 자주 나옴)이면 같은 동네 검색 외에 `{카테고리}+{근처 목적지 상권 2곳}`(예: 한남 디저트, 연남 디저트)과 인스타 해시태그 상위에서 같은 가격대 2~3곳을 **'목적지 경쟁'**으로 따로 적는다.
6. 실측이 안 되면(화면이 안 열림, 상위가 경쟁이 아닌 정보 글뿐) "경쟁 실측 못 함 — 업종 파일 가설"로 적고 3단계 채널 등급에서 가설로만 쓴다.

## 5) 손님이 실제로 쓰는 말 상위 10개

1. 방문자 리뷰 최근 30~50개를 읽는다(스크립트 `mk.py place`가 리뷰 문장을 주면 그걸 쓴다).
2. 반복되는 말을 칭찬·불만으로 나눠 센다(예: "크루아상 결" 9, "주차 불편" 4).
3. 상위 10개를 손님이 쓴 표현 그대로 적는다. 이 말이 나중에 제목·훅·포지셔닝의 재료가 된다.
4. **같은 불만(맛·위생·응대·양)이 반복되면** 콘텐츠보다 먼저 알린다: "리뷰에 '응대가 느리다'는 말이 최근 한 달에 5번 있어요. 홍보보다 이걸 먼저 보시는 게 좋겠어요."

## 6) 업종 카테고리와 규제 플래그 정하기

1. `guides/industries/index.md`를 열어 가장 가까운 업종 파일 1개를 고른다. 플레이스 업종 표시를 먼저 참고한다.
2. 그 파일의 **규제 플래그**를 모두 적는다(예: 의료, 식품 효능, 학원 교습비). 의료 같은 높은 규제 플래그면 2단계 전에 사장님께 한 줄로 먼저 알린다(확인 메시지 안에 넣는다).
3. 업종 파일의 채널 순서는 **가설**이다. 4)의 경쟁 실측과 다르면 실측을 따른다(3단계 채널 등급).
4. 맞는 업종이 없으면 가장 가까운 것 + "업종 안 맞음"을 적고, 나중에 제보를 권한다(`guides/feedback.md`).

## 7) 이미 운영 중이면 (②·③ 갈래): 기존 글 분석

1. 사장님 블로그·인스타 최근 10편을 읽는다(스크립트: `python3 mk.py blog-list {블로그ID}` → `python3 mk.py read-blog {주소} --max-chars 1500`).
2. 말투 4가지를 적는다: 말투(격식체/해요체/섞음/일기체), 이모티콘(없음/조금/많음), 화자(가게 이름/저희/저는), 길이(블로그는 1,000자 미만/1,000~2,000자/2,000자 이상).
3. 반응 상위 3편과 하위 3편을 고르고, 상위 3편의 공통점(주제·사진·첫 문장)을 한 줄로 적는다.
4. 실제 문장 2개를 그대로 옮겨 둔다(브랜드 프로필 "말투" 칸에 쓴다).

## 결과 정리 양식 (기억 + 프로필 초안)

`[조사 결과 — 날짜 기준]` 아래에 한 줄씩: 가게·지역·업종 파일·규제 플래그 / 플레이스(상태: 찾음·위치 확인 못 함·미등록·확인 중, 리뷰 수, 최근 30일, 답글 n/10, 별점, 빈칸) / 블로그(사장님 글·손님 후기 수·협찬 비율) / 인스타·유튜브(팔로워, 최근 30일, 반응 최고 주제) / 경쟁 3~5곳 / 우리 순위 / 손님 말 상위·불만 / 말투(운영 중일 때) / **확인 못 함**(로그인·화면 안 열림 등). 못 본 칸은 비워 둔다.

## 확인 메시지 (사장님께, 짧게) — 규칙

- **조사에서 실제로 본 것만** 쓴다. 못 본 칸은 줄을 빼거나 "못 찾았어요"로 쓴다. 아래 예시의 메뉴·리뷰 말을 그대로 쓰지 않는다.
- **숫자 번호(1. 2. 3.)는 한 메시지에 한 묶음만, 늘 상황 갈래에 쓴다**(그래야 "3번이요"가 늘 같은 뜻이다). 못 찾았을 때 묻는 등록 상태는 **가·나·다**로 쓴다. 나머지는 "틀린 곳만 적어 주세요".
- 질문은 2개까지. 찾았을 때: 상황 번호 + 지역 충돌·온라인 판매·인스타 주소 중 꼭 필요한 1. 못 찾았을 때: 상황 번호 + 등록 상태(가·나·다). 상권(동네형·목적지형)처럼 업종 갈래는 추정 한 줄로 넣는다.
- 질문 수 밖(답 횟수는 그대로, 이 메시지에 한 줄씩): **식품 업종**(카페·베이커리·디저트·식당·반찬 등)은 "영업신고증에 적힌 업종이 휴게음식점·일반음식점·제과점영업·즉석판매제조가공업 중 어느 거예요?"(필수 사실, 예외가 이걸로 갈린다 — `guides/compliance/food-origin.md` 1). **의료 등 높은 규제**는 6)의 알림 한 줄도 여기에 넣는다(따로 보내지 않는다).
- 상황 문구는 갈래마다 아래 말로 쓴다. "멈춤·방치·실패" 같은 말은 쓰지 않는다: 1. 이제 막 시작하는 단계 / 2. 꾸준히 올리고 계신 상태 / 3. 채널을 잠시 쉬고 계시거나 대행사를 쓰셨던 상태 / 4. 오픈 준비 중 / 5. 매장 없이 온라인·외주로 하시는 일

조사 결과가 있을 때 (숫자 번호 = 상황 1~5 한 묶음뿐):
```
가게를 먼저 살펴봤어요. 이렇게 파악했는데 맞나요?
- 망원동 카페, 메뉴판에 보이는 대표 메뉴는 [조사에서 본 메뉴 2~3개]
- 손님들은 리뷰에서 "[리뷰에 실제로 많이 나온 말]"을 가장 많이 말해요
- 플레이스에 [비어 있는 칸]이 비어 있어요
- [상권 추정] 일부러 찾아오는 손님이 많은 가게로 보여요 (동네 단골 위주면 알려 주세요)
지금 상태는 어느 쪽에 가까워요? (저는 2번으로 봤어요)
1. 이제 막 시작하는 단계  2. 꾸준히 올리고 계신 상태  3. 채널을 잠시 쉬고 계시거나 대행사를 쓰셨던 상태
4. 오픈 준비 중 (오픈 예정일도요)  5. 매장 없이 온라인·외주로 하시는 일
번호 하나와, 틀린 곳만 적어 주세요.
```

조사 결과가 거의 없을 때(가게를 못 찾음 — 상황 1~5 + 등록 상태 가~다):
```
가게를 먼저 찾아봤는데, 네이버 지도·블로그에서 '[상호]'가 나오지 않았어요.
- 업종은 [업종]으로 보고 준비할게요
- 인스타 [계정이 보이면 주소 / 안 보이면: 계정이 있으면 주소를 알려 주세요]
지금 상태는 어느 쪽에 가까워요? (저는 [추정] 번으로 봤어요)
1. 이제 막 시작하는 단계  2. 꾸준히 올리고 계신 상태  3. 채널을 잠시 쉬고 계시거나 대행사를 쓰셨던 상태
4. 오픈 준비 중 (오픈 예정일도요)  5. 매장 없이 온라인·외주로 하시는 일
네이버 지도 등록은요? 가. 등록돼 있어요(지도 앱에서 가게 → '공유' → '링크 복사'해 붙여 주세요)  나. 아직 안 했어요  다. 잘 모르겠어요
예) "3번, 가" 처럼 보내 주세요.
```

- 등록 상태 답은 위 표(가·나·다)대로 한다. 상황 번호만 오고 가·나·다가 없으면 "다(모름)"로 보고 확인 방법을 준다. 틀렸다고 한 것만 고친다. 사장님 답은 조사보다 우선한다.
- **중간부터 요청**(SKILL.md)이면 이 메시지를 보내지 않는다. 결과물을 먼저 내고, 결과물 메시지 맨 아래 한 줄: "네이버 지도에서 '[상호]'가 안 보였어요. 등록돼 있으면 지도 앱 '공유' → '링크 복사'로 붙여 주세요." 답 전까지 플레이스 칸은 "확인 중".
- 확인이 끝나면 결과를 기억에 저장하고 **바로 '이번 주 먼저 고칠 3가지'를 보낸다**(`guides/03-strategy.md` 3)). 질문은 그다음이다. 그다음 `guides/02-interview.md`로 간다.
