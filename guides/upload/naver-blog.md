# 네이버 블로그 올리기

## 0) 계정이 없으면 새로 열기 (있으면 건너뜀)
1. 만들기: 사장님 네이버 아이디로 블로그(blog.naver.com)에 들어가면 블로그가 열린다. 로그인은 사장님. 블로그 이름·별명은 가게 이름으로.
2. 프로필 채우기: 브랜드 프로필의 사실 자료로 가게 이름·소개 한 줄·주소·영업시간·연락처·링크를 블록으로 만들어 주고, 사장님이 앱에서 붙여넣는다(대표 사진은 파일로). 없는 값은 지어내지 말고 사장님께 묻는다.
3. 첫 3개 게시물 계획: ① 가게 소개(누가·어디서·무엇을) ② 대표 상품·서비스 1개 ③ 가게 이야기 또는 오늘의 모습. 사장님 승인 뒤 하루 간격으로 올린다(하루 상한은 `guides/upload/index.md` 4-1).

- 공식 게시 API: **없음.** 네이버는 API 글쓰기를 2020-05-06에 종료했다(블로그팀 공지, 이유: 기계적 대량 발행).
- 경로: **붙여넣기 묶음 → 사장님이 폰 블로그 앱에서 발행. 이것 하나뿐이다.** 너는 네이버에 로그인하지 않고, 글을 넣지 않고(임시저장 포함), 발행·예약하지 않는다. 이유와 사장님께 할 말은 `guides/upload/index.md` 1)·3).
- 노출 확인은 `guides/make/blog-naver.md` 10)대로 한다: 키가 있으면 `mk.py search-blog`(공식 API), 없으면 사장님 폰 검색 화면 캡처. 네가 네이버에 검색어를 넣어 확인하는 것은 사장님 동의 뒤에만(`guides/01-research.md` 공통 규칙 ③).
- 계정 만들기·프로필 칸 채우기도 사장님이 폰에서 한다. 너는 넣을 문구를 묶음으로 준다.

## 1) 묶음 만들기 전 점검 (사람이 발행해도 누락되는 이유들)

| 규칙 | 할 일 |
|---|---|
| 하루 1편, 많아도 2편 | 2편이면 4시간 이상 띄운다. 사장님이 PC에서 예약을 쓰더라도 여러 개를 한꺼번에 걸지 않게 안내한다 |
| 같은 틀 반복 금지 | 최근 3편과 제목 구조·첫 문장·소제목 순서·마무리 문구를 비교해 겹치면 바꾼다. 같은 주제를 문장만 바꿔 여러 편 내지 않는다 |
| 사장님 경험 1가지 이상 | 실제 사진, 가게 사정, 손님 이야기 중 하나. AI 원고만으로 된 글은 내지 않는다 |
| 링크는 글당 1개 이하 | 협찬·제휴 링크 여러 개는 누락 후기에서 반복해 나왔다 |
| 주제를 섞지 않는다 | 가게 블로그에 뉴스 요약이나 관계없는 글을 넣지 않는다 |
| 'AI 활용' 표시 | AI 이미지·영상이 하나라도 있으면 블록 0에 "AI 활용 켜기"를 넣는다(`guides/make/blog-naver.md` 8)) |

## 2) 묶음 보내기

1. `guides/upload/index.md` 6)의 형식으로 만든다(사진 이름 `사진1_…jpg`, 블록 0~5).
   - 본문은 맨 텍스트. 네이버 도움말도 서식이 섞인 글을 복사하면 오류가 날 수 있다고 안내한다.
   - 사진 수는 글 유형대로(방문형 후기·소개 15~25장, `guides/make/blog-naver-types.md`). 본문 끝에 사진1부터 한꺼번에(사진1 = 대표 사진, 제목 글자를 얹은 표지 이미지).
2. 사장님 폰으로 보낸다. 바로 올리기 어려우시면: "붙여넣기만 하고 저장해 두셨다가, 앱 첫 화면 '임시저장글'에서 이어서 발행하셔도 돼요."
3. 글 주소를 받아 기록한다.

## 2-1) 선택: 에이전트가 '임시저장'까지 (위험 중간, 사장님이 고를 때만)

사장님이 붙여넣기도 번거롭다고 하면 한 번만 제안한다. 발행은 여전히 사장님이 한다.
- 안내: "제가 블로그에 글을 넣어 '임시저장'까지 해 두고, 사장님은 폰 앱 '임시저장글'에서 발행만 누르는 방법도 있어요. 이렇게 쓰는 분들이 문제를 겪었다는 후기는 아직 못 봤지만, 네이버 약관은 자동 입력을 막고 있어서 완전히 안전하다고는 말씀 못 드려요. 해 볼까요? (1번 해 보기 / 2번 지금처럼 붙여넣기)"
- 조건(하나라도 안 되면 하지 않는다):
  1. 로그인은 사장님이 평소 쓰는 기기·브라우저에서 **직접** 한다. 에이전트는 아이디·비밀번호를 입력하거나 저장하지 않는다.
  2. 새 자동화 브라우저를 띄우지 않는다. 사장님이 로그인한 브라우저 안에서만 작업한다.
  3. 에이전트는 **발행·예약 발행을 누르지 않는다.** 하루 1편만 임시저장한다.
  4. 영수증 퀴즈·보호조치·캡차가 뜨면 즉시 멈추고 이 방식을 끈다(4) 표).
- 근거: 에이전트가 로그인·발행까지 한 후기는 검색 누락·보호조치가 반복됐고, 사람이 로그인하고 임시저장까지만 맡긴 후기는 문제 보고가 없었다(2026-09~11 본인 후기, 표본 적음).

## 3) 첫 2주: 매 글 노출 확인

1. 발행 다음 날 노출을 확인한다(방법은 `guides/make/blog-naver.md` 10): 키 있으면 공식 API, 없으면 사장님 캡처).
2. 날짜·노출 여부를 기록한다.
3. **2편 연속 안 보이면 발행을 멈추고** 사장님께 알린다: "최근 두 글이 검색에 안 보여요. 1~2주 쉬었다가 다시 올리는 게 안전해요." 쉬는 동안 다음 글은 만들어 두기만 한다.
4. 2주가 지나도 문제가 없으면 이후엔 주 1회 몰아서 확인한다.

## 4) 위험 신호가 오면

| 상황 | 할 일 |
|---|---|
| 사장님이 "아이디 보호조치", "영수증 퀴즈", 보호조치 메일을 받았다 | 그날 네이버 관련 일을 모두 멈춘다. 사장님이 직접 본인 확인으로 풀게 안내한다. 같은 일이 두 번째면 풀리지 않을 수 있다고 알린다 |
| "게시글이 더 이상 등록되지 않음" | 하루 등록 수 제한. 다음 날로 미룬다 |
| 글쓰기 제한·경고 알림 | 발행을 멈추고 알림 문구를 받아 기록한다. 원인 추정은 단정하지 않는다 |
| 사장님이 "그냥 네가 올려 줘" | `guides/upload/index.md` 3)의 답으로 거절하고 묶음을 보낸다 |

## 아직 확인 안 된 것 (사장님께 단정하지 않는다)
- 앱에 붙여넣을 때 줄바꿈이 그대로 유지되는지, 사진 여러 장 한 번에 선택이 되는지.
- 앱의 장소·태그·인용구 버튼 위치(사장님 화면 캡처로 맞춘다).
