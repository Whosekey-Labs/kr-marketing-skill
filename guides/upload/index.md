# 업로드: 원칙과 공통 절차

콘텐츠가 검수를 통과하고 사장님이 내용을 승인한 뒤에만 이 파일을 연다. 플랫폼별 연결 방법은 그 플랫폼 파일만 연다(아래 표).

## 1) 원칙: 무료 공식 API가 있으면 API, 없으면 네 브라우저. 단 네이버·틱톡은 사장님 폰

**네이버(블로그·클립·스마트플레이스)와 틱톡은 예외다. 너는 이 두 곳에 로그인하지도, 발행·예약하지도 않는다.** 글 넣기는 기본으로 하지 않고, 네이버 블로그만 사장님이 고르면 '임시저장까지' 조건부로 한다(`guides/upload/naver-blog.md` 2-1). 네이버·틱톡 밖에서 붙여넣기 묶음(6절)을 만들어 사장님 폰으로 보내고, 사장님이 앱에서 붙여넣어 발행한다. 2026년 9~11월에 AI·자동화 도구로 네이버에 로그인·발행한 블로그가 검색 누락이나 아이디 보호조치를 받았다는 본인 후기가 여러 건(도구가 직접 발행한 경우만 엄격히 세면 4~5건, 로그인 단계 보호조치 1건) 나왔고, 틱톡도 자동 업로드 영상만 조회수가 0이었다는 보고가 반복됐다. 두 곳 약관 모두 수량과 상관없이 자동화 로그인·게시를 금지한다.

| 플랫폼 | 경로 | 열 파일 | 예약 기능 |
|---|---|---|---|
| 유튜브(쇼츠) | API | `guides/upload/youtube.md` | API `publishAt`, 스튜디오 [예약] |
| 인스타그램 | API(릴스는 파일 그대로 가능), 막히면 Business Suite | `guides/upload/instagram.md` | Business Suite(사진 10장까지) |
| 페이스북 페이지 | API | `guides/upload/instagram.md` | API 10분~30일, Business Suite 20분~29일 |

| 네이버 블로그 | **붙여넣기 묶음(사장님 폰)** | `guides/upload/naver-blog.md` | 쓰지 않음(앱은 바로 발행만) |
| 네이버 클립 | **붙여넣기 묶음(사장님 폰)** | `guides/upload/naver-clip.md` | 쓰지 않음 |
| 스마트플레이스 새소식 | **붙여넣기 묶음(사장님 폰)** | `guides/upload/smartplace.md` | 없음 |

| 카카오톡 채널 소식 | 브라우저 | `guides/upload/kakao-channel.md` | 소식 예약 발행 |
| 틱톡 | **붙여넣기 묶음(사장님 폰)** | `guides/upload/tiktok.md` | 쓰지 않음 |

- API는 돈이 들지 않지만 처음 연결(개발자 앱·토큰 만들기)이 어렵다. 사장님은 개발을 모른다는 전제로, 연결 작업은 **네가 브라우저로 대신 누르고**, 사장님은 로그인·인증번호·"허용"만 한다(플랫폼 파일에 화면 순서대로, 사장님 일만 굵게).
- **15분 규칙:** 연결을 시작한 시각을 적는다. 15분 안에 안 끝나거나 같은 화면에서 두 번 막히면, 그 플랫폼의 브라우저 경로로 내려간다(인스타·페이스북 = Meta 비즈니스 스위트, 유튜브 = 스튜디오 또는 사장님 폰). 네이버·틱톡은 브라우저 경로가 없다.
- 사장님께 오류를 받을 때는 **"오류 화면이 나오면 화면을 캡처해서 보내 주세요"** 라고 한다. 주소 복사를 부탁하지 않는다.
- 유튜브 첫 업로드는 **비공개**로 올리고 사장님이 확인한 뒤 공개한다(`upload_api.py youtube` 기본값이 비공개).
- 틱톡은 공개 게시 API가 있지만 사장님 개인용 앱은 심사를 통과할 수 없다(틱톡 지침: "Apps must not be for private or personal use."). 그래서 사장님 폰이다.
- 카카오톡 채널 **메시지**(친구에게 보내는 것)는 유료(건당 15~20원, VAT 별도)다. 너는 초안만 만들고 발송·예약은 사장님이 한다.
- API 게시는 도우미 `tools/upload_api.py`를 쓴다(스크립트 모드일 때). **`--live`가 없으면 시험 실행일 뿐 아무것도 보내지 않는다**(출력에 "DRY-RUN(실제로 안 보냄)"). 시험 결과를 성공으로 보고하지 않는다. 사장님 승인 뒤에만 `--live`로 실제 게시한다.
- 연결 열쇠(토큰)는 네 금고(비밀 값 저장)나 비공개 메모에 두고, 실행할 때 환경 변수로 넘긴다: `IG_ACCESS_TOKEN=… IG_USER_ID=… python3 upload_api.py instagram-image … --live`. 채팅·문서·브랜드 프로필에 값을 쓰지 않는다.
- 플랫폼 계정이 아예 없으면 그 플랫폼 파일 맨 앞의 "계정이 없으면 새로 열기"부터 한다(만들기 → 프로필 채우기 → 첫 3개 게시물 계획).

## 2) 승인 방식: 첫 업로드 직전에 한 번

1. 승인 방식은 이 스킬에서 **여기 한 곳에서만, 첫 글을 올리기 직전에** 묻는다(인터뷰·계획 단계에서 미리 묻지 않는다).
2. 답을 브랜드 프로필의 "승인 방식" 칸에 날짜와 함께 적는다. 칸에 답이 이미 있으면 다시 묻지 않는다.

> "이제 처음으로 올리려고 해요. 앞으로 어떻게 할까요?
> 1) 매번 확인: 올리기 직전 화면을 보여 드리고 '올려'라고 하시면 올릴게요.
> 2) 처음 몇 주만 확인: 처음 몇 주(예: 4주) 동안은 매번 보여 드리고, 그 뒤엔 계획대로 올리고 결과만 알려 드릴게요.
> 3) 계획 승인 후 올리기: 이번 주 계획을 승인하시면 그 안의 글은 정해 둔 시간에 올리고 결과만 알려 드릴게요."

- "계획 승인 후 올리기"여도 다음은 **매번** 확인한다: 돈이 드는 일(카카오 메시지·광고), 삭제, 계획에 없던 글, 법규 검수에서 "확인 필요"가 남은 글.
- 사장님이 바꾸라고 하면 바로 바꾸고 칸을 고친다.
- **답이 서로 부딪히면 확인 질문 1개만**(SKILL 규칙 3). 예: 앞서 "인스타는 제가 직접 올려요"라고 했는데 여기서 "알아서 올리고 결과만"이라고 하면 채널별로 갈라 묻는다:
  > "인스타는 사장님이 직접 올리시고, 나머지(플레이스 소식·블로그 등)는 제가 계획대로 올리고 결과만 알려 드리면 될까요? 인스타도 제가 올릴까요?"
  답 전까지 인스타는 '사장님이 직접'(붙여넣기 묶음, 6))으로, 나머지는 더 안전한 1) 매번 확인으로 둔다. 답을 받으면 "승인 방식" 칸에 채널별로 적는다(예: 인스타=사장님 직접 / 그 외=3)).

## 3) 네이버·틱톡: 사장님께 이유 알리기 (처음 한 번)

네이버나 틱톡에 처음 올릴 때, 묶음을 보내기 전에 한 번만 말한다. 말한 날짜를 "내 요청사항"에 적는다.
> "네이버랑 틱톡은 제가 직접 올리지 않고, 글과 사진을 정리해 드리면 사장님이 폰에서 올려 주세요(1~2분이면 돼요). 올해 AI 프로그램이 대신 로그인해서 올린 블로그가 검색에서 빠지거나 아이디가 잠겼다는 후기가 여러 건 있었어요. 두 곳 약관도 프로그램으로 올리는 걸 금지하고 있어요."

- "무조건 막힌다"처럼 단정하지 않는다. 후기는 본인 주장이고 원인이 확인된 것은 아니다.
- 이 조항은 최근에 생긴 것이 아니다(2025-07-10 시행판에도 같은 문장). "최근 강화됐다"고 말하지 않는다.
- 사장님이 "그래도 네가 올려 줘"라고 하면: "사장님 아이디가 잠기면 두 번째는 풀리지 않을 수도 있어서, 이건 제가 하지 않을게요"라고 답하고 묶음을 보낸다.
- 카카오·당근·Meta는 게시 자동화를 이름으로 금지하는 조항이 확인되지 않았다. 따로 고지하지 않는다.

## 4) 브라우저 공통 절차

네이버·틱톡에는 쓰지 않는다(1절). 아래는 API가 없는 나머지 플랫폼(티스토리·당근·카카오 채널 등)용이다.

### 처음 한 번 (플랫폼마다)
1. 로그인은 **사장님이 직접** 한다. 비밀번호를 채팅으로 받지 않는다.
   - 네 브라우저에 로그인 금고(저장 기능)가 있으면 사장님이 직접 넣고 저장하게 안내한다(예: 피클은 로그인 카드 → "금고에 저장", 값은 AI에게 전달되지 않음).
   - 없으면 브라우저 화면을 사장님께 넘겨 직접 로그인하게 한다.
2. 다음 날 다시 열어 로그인이 유지되는지 확인한다.

### 올릴 때마다
1. 올릴 내용(제목·본문·사진·해시태그·게시 시각)이 사장님 승인을 받았는지 확인한다.
2. 파일(JPEG/PNG 사진, mp4)을 네 브라우저가 열 수 있는 위치에 둔다.
3. 그 플랫폼의 PC 웹 작성 화면을 연다.
4. **사람처럼 입력한다.**
   - 제목·본문은 붙여넣기 대신 한 글자씩 타이핑한다.
   - 화면은 자연스럽게 스크롤하고, 버튼 사이에 사람 속도(몇 초)로 쉰다.
   - 같은 시각에 여러 플랫폼·여러 글을 몰아 올리지 않는다. 한 사장님 계정만 다룬다.
5. 파일을 첨부한다(업로드 창 또는 끌어놓기). 사진 순서를 확인한다.
6. 보안문자(캡차)·본인인증·"새 기기 로그인" 확인이 뜨면 **즉시 멈추고 화면을 사장님께 넘긴다.** 절대 우회하지 않는다. 그날은 그 플랫폼에서 더 하지 않는다. 같은 일이 두 번 생기면 그 플랫폼도 붙여넣기 묶음으로 바꾼다.
7. 미리보기 화면을 캡처해 사장님께 보낸다.
8. 승인 방식대로 마지막 버튼을 누른다. 플랫폼에 예약 기능이 있으면 **예약으로 걸어 두는 것**을 먼저 쓴다(5절).
9. 게시물 주소와 캡처를 남기고 짧게 보고한다: "올렸어요. 링크: … / 예약 시각: …"

## 4-1) 공통 수치 (이 표가 기준. 다른 파일은 이 표를 가리킨다)

| 항목 | 값 | 근거 |
|---|---|---|
| 하루 게시: 네이버 블로그 | 1편(많아도 2편, 2편이면 4시간 이상 띄움). 예약을 한꺼번에 여러 개 걸지 않는다 | 네이버는 하루 등록 수를 제한하고(수치 비공개) "천천히 글을 등록하길" 권한다. 사람이 짧은 시간에 예약을 몰아 걸었다가 보호조치를 받은 후기도 있다 |
| 하루 게시: 네이버 클립·스마트플레이스·당근·카카오 소식·티스토리 | 1건 | 도배로 보이지 않게 |
| 하루 게시: 인스타·페이스북·스레드·유튜브·틱톡 | 2건(틱톡은 1~2개) | 공식 한도는 훨씬 크지만 소상공인 계정에 그 이상은 필요 없다 |
| 숏폼 길이 | 15~45초 기본, 이야기·정보형 30~90초, **90초 이하**(유튜브 쇼츠는 60초 이하 권장) | 페이스북 릴스 공식 3~90초. 쇼츠는 1분 넘고 저작권 신고에 걸리면 전 세계 차단 가능 |
| 숏폼 글자 안전 영역(1080×1920) | 글자는 **x 65~890, y 270~1250** 안. 위 270·아래 670·왼쪽 65·오른쪽 190px 비움 | 위 14%·아래 35%·양옆 6%는 Meta 릴스 광고 가이드. 오른쪽 190px과 다른 플랫폼 적용은 실무 값 |
| 로고·워터마크 | 이미지·영상 안에 넣지 않는다. 가게 이름은 표지·마지막 장 글자로만 | 다른 플랫폼 워터마크는 클립·틱톡에서 불이익 |

## 5) 예약 기능 먼저 쓰기

정해진 시각에 네가 깨어나 로그인할 필요가 없도록, 승인받은 글은 플랫폼 자체 예약에 걸어 둔다. 사용량 한도 때문에 예약 작업이 건너뛰어지는 위험도 피한다.

| 도구 | 기간 | 메모 |
|---|---|---|
| Meta 비즈니스 스위트 | 페이스북 페이지 20분~29일 | 무료. 인스타 사진은 10장까지. 인스타 예약 기간은 원문 없음 |
| 카카오톡 채널 소식 | 최대 기간 원문 없음 | [예약] 탭에서 확인 |
| 유튜브 | API `publishAt`, 스튜디오 [예약] | 최대 기간 원문 없음 |

네이버·틱톡은 사장님이 폰에서 바로 발행하므로 이 표에 없다.

## 6) 붙여넣기 묶음 (네이버·틱톡 기본, 다른 곳이 막혔을 때도)

목표: **사장님 손 1~2분.** 너는 그 플랫폼에 접속하지 않는다. 형식 예시는 `examples/paste-bundle-naver-blog.md`.

### 사진 먼저 보내기
1. 사진 파일 이름을 넣을 순서대로 바꾼다: `사진1_크루아상단면.jpg`, `사진2_진열대.jpg` … (번호는 앞에, 짧은 설명은 뒤에).
2. 공유 폴더 하나(예: 구글 드라이브 "블로그_11월20일")에 넣고 링크를 보낸다. 폴더를 못 만들면 네 에이전트가 쓸 수 있는 방법(보관함 다운로드·메일 등)으로 보낸다.
3. 사장님은 폴더에서 **전체 선택 → 폰에 저장**만 하면 된다. 앨범에서 고를 때 이름 번호 순서대로 고르면 된다.

### 글은 블록으로 나눠 보내기
메신저로 보낼 수 있으면 **블록마다 메시지 하나씩** 보낸다(길게 눌러 복사 한 번 = 블록 하나). 문서 하나로 줄 때는 블록 사이에 `━━━━━━` 줄을 넣는다. 맨 텍스트만 쓴다(서식 없음).

| 블록 | 내용 |
|---|---|
| 0. 순서표 | 아래 사장님 단계(번호) + 사진 폴더 링크. 보기만 하는 블록 |
| 1. 제목 | 제목 한 줄만 |
| 2. 본문 | 문단 사이 빈 줄. 소제목은 `【소제목】` 한 줄로. 굵게·표·사진 자리 표시는 빼고 맨 문장으로 |
| 3. 사진 순서 | `사진1 → 사진7, 번호 순서대로 한 번에` 한 줄 + 대표 사진이 무엇인지. 보기만 하는 블록 |
| 4. 태그 | `#밀과결 #망원동빵집 …` 한 줄(3~7개) |
| 5. 장소 | 앱에서 검색할 가게 이름 한 줄 |

- `guides/make/` 순서표의 `[사진n]` 자리는 묶음에서 뺀다. 사진은 본문 끝에 사진1부터 한꺼번에 넣는다(사진1이 첫 사진 = 대표 사진). 문단 사이마다 끼우면 3~5분이 걸린다.
- `【소제목】` 줄은 그대로 둬도 읽힌다. 시간이 있으면 그 줄만 앱의 인용구로 바꾸면 된다(선택, 블록 0에 "선택"이라고 적는다).
- 링크는 글 하나에 1개 이하. 빈칸(`[직접 입력]`)이 하나라도 남았으면 묶음을 보내지 않는다.

### 사장님 단계 (블록 0에 그대로 넣는다. 네이버 블로그 기준)
1. 사진 폴더 열기 → 전체 선택 → 폰에 저장
2. 블로그 앱 → 글쓰기
3. 제목 칸에 블록 1 붙여넣기
4. 본문에 블록 2 붙여넣기
5. 본문 맨 끝에서 사진 버튼 → 사진1부터 번호 순서대로 한 번에 선택
6. 장소 버튼 → 블록 5 검색해서 추가
7. 태그 칸에 블록 4 붙여넣기 → [발행]
8. 올라간 글 주소를 복사해서 보내 주기

클립·스마트플레이스·틱톡은 그 플랫폼 파일의 B절 단계를 쓴다(같은 블록 방식).

### 보낸 뒤
- 사장님이 링크를 보내면 기록한다. 하루가 지나도 답이 없으면 한 번만 묻는다: "어제 보낸 글 올리셨어요?"
- 앱 화면의 버튼 이름·위치는 원문으로 확인하지 못한 부분이 있다(사진 여러 장 한 번에 선택, 붙여넣은 줄바꿈 유지, 태그 칸 위치). 사장님이 "버튼이 안 보여요"라고 하면 화면 캡처를 받아 그 화면 기준으로 다시 알려 주고, 고친 단계를 기록한다.
