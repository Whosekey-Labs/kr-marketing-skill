# 카드뉴스 만들기

유형·스타일 목록은 `guides/styles/cardnews.md`, 디자인 키트는 `guides/07-design-kit.md`, 레퍼런스 고르기는 `guides/06-reference.md`. 이번 주 기획에서 이미 찾은 레퍼런스가 있으면 다시 찾지 않고 그것을 쓴다(같은 업종 카드뉴스가 3개 안 되면 그만큼만 더 찾는다).

브랜드 프로필이 없으면 최소 프로필(업종·규제 플래그·말투 한 줄·금지 표현·사실 자료)만 만들고 바로 제작한다(`guides/00-start.md` 중간 요청 규칙). 사장님 대상 글에서 쓰지 않는 표현은 `guides/compliance/common.md`의 '반감 부르는 표현'.

## 규격 (항상)

| 항목 | 값 |
|---|---|
| 크기 | **1080×1350(4:5)**. 인스타 앱(최대 3:4)과 API(최소 4:5)를 모두 만족하는 값 |
| 파일 | **JPEG, sRGB, 장당 8MB 이하** (인스타 API 조건) |
| 장수 | **10장 이하**(인스타 최대 20장이지만 10장 이하가 90%) |
| 핵심 글자 자리 | **가운데 1080×1080 안**(위아래 135px 비움). 표지 핵심 글자는 **가운데 1012px 폭 안**도 지킨다(프로필 격자 3:4에서 좌우가 잘림) |
| 로고·워터마크 | **넣지 않는다.** 인스타 추천 조건이 "보이는 워터마크 없음"이다. 가게 이름은 표지·마지막 장에 글자로 쓰거나 `account`(계정 이름 글자)로 넣는다 |
| 글자 크기 | 표지 제목은 자동(가장 긴 줄이 폭 90%), 장 제목·질문 **96~112px**, 본문 **최소 40px** |
| 배치 | 본문은 **위에서부터** 아래까지 채운다(가운데 몰림 없음). 쪽번호·진행 막대(`chrome`)는 기본 끔, '넘겨서 보기 →'는 표지에만 |
| 색 | 메인 1 + 강조 1 + 중립색(흰·먹색·회색). 강조는 한 장에 2곳까지 |

## 절차

### 1) 레퍼런스 3~5개로 디자인 문법 뽑기 (생각만, 사장님께는 한 줄 요약)

> **처음 디자인을 정할 때 한 번만** 3~5개를 본다. 정한 디자인 문법은 브랜드 프로필에 저장하고, 그다음 주부터는 다시 찾지 않고 이번 소재용 레퍼런스 1~2개(`guides/06-reference.md`)만 본다.

디자인은 사장님 홈페이지·로고 색을 기본으로 따라가지 않는다. **같은 업종에서 반응 좋은 카드뉴스**에서 출발한다.

1. 같은 업종에서 반응 좋은 카드뉴스 3~5개를 고른다(저장·댓글이 그 계정 평소보다 많은 것). 같은 동네 경쟁 가게 것은 빼고, 다른 업종 1개는 더해도 된다.
2. 각각 아래 표를 채운다(채팅에 다 보여 주지 않는다). 못 본 수치는 '확인 못 함'.

| 칸 | 적을 것 |
|---|---|
| 유형·장별 역할 | C01~C12 중 무엇, 1장 ○○ → … → 마지막 장 ○○ |
| 표지 훅 | 숫자형·질문형·혜택형·제품명형·경고형 중 무엇, 표지 글자 수 |
| 위계 | 제목·소제목·본문이 몇 단계로 보이나, 제목이 화면의 몇 % |
| 여백 | 넓음/보통/빽빽 |
| 사진 비중 | 사진이 장 전체/절반/작은 칸/없음 |
| 글자 크기 | 표지 제목·본문이 커 보이나 작아 보이나 |
| 색 쓰는 법 | 색 몇 개, 강조색을 어디에(글자/면/선), 바탕이 밝나 어둡나 |
| 가져올 것 | 3~5개에서 공통으로 보이는 것 2~3개 |

3. 공통점을 사장님이 고른 갤러리 스타일(`guides/styles/cardnews.md` 4절, S01~S11)과 합쳐 디자인을 정한다.
4. **구조와 문법만 빌리고 문장·사진·사례는 우리 것으로** 바꾼다. 남의 이미지·문장은 쓰지 않는다.

### 2) 장별 원고

1. 유형의 장 구성(`guides/styles/cardnews.md` 2절)대로 장을 나눈다.
2. 글자 수 기준(**권장**. 소재가 모자라면 장수를 줄이고 필요한 자료를 구체적으로 부탁한다. 지어내서 채우지 않는다):

| 칸 | 기준 |
|---|---|
| 표지 제목 | **12~19자**(공백 빼고), 2줄. 한 줄 9자 안팎 |
| 본문 | **장당 80자 안팎**(40~120자). 넘으면 장을 나눈다 |
| 마지막 장 | **할 일 1개**(예약·방문·저장 중 하나) + 지역명 |
| 장수 | 10장 이하. 이벤트·공지 3~4장, 메뉴 4~6장, 정보 6~8장 |

3. 가격·시간·기간·효능·후기는 **사장님 자료로만** 쓴다. 없으면 `[직접 입력: 가격]`으로 두고 사장님께 묻는다. 렌더 점검에서 이 빈칸은 **고칠 것**이다(채워야 올린다).
4. **장마다 숫자 하나나 예 하나**를 넣는다("빨리 구워요" 대신 "하루 두 번, 11시·15시"). 그 숫자·예가 그 장의 시각 앵커가 된다(`guides/make/cardnews-spec.md` 앵커 표).
5. **CTA 바로 앞에 저장용 요약 장**을 둔다("저장해 두세요" + 체크리스트 3~4줄). 정보형(C05·C06·C07)은 꼭, 나머지는 장수가 5장 이상이면.
6. 장마다 레이아웃을 바꾼다: 같은 틀 2장 연속은 주의, 3장 연속은 고칠 것. 바탕도 3장 연속 같지 않게 `tone`(light·brand·deep)을 섞는다.
7. 강조할 단어는 `*별표*`로 감싼다(한 장에 2곳까지). 그리는 법은 `em_style`(marker·box·color).
8. 법규 검수(`guides/compliance/`)를 원고 단계에서 먼저 돌린다. 이미지가 된 뒤 고치면 다시 렌더해야 한다.

### 3) 디자인 정하기 + 시안 2안

1. 첫 카드뉴스는 묻지 않고 표지+본문 1장씩 **시안 2안을 만든다**(첫 정식 제작 때. 중간부터 요청받은 첫 결과물은 1안만 만들고 2안은 다음에 제안. 같은 원고, `guides/07-design-kit.md` 1)).
   - 1안(A안) 레퍼런스안 — 1)의 문법 그대로. **고르기 전 기본.**
   - 2안(B안) 기존 색 살린 안 — 같은 문법 + 기존 가게 색(로고·간판·홈페이지). 기존 색이 없으면 같은 성격 카드의 다른 스타일 후보.
   > "두 가지로 만들어 봤어요. 마음에 드는 쪽 1번/2번, 번호만 알려 주세요. 1번은 같은 업종에서 반응 좋은 방식, 2번은 사장님 가게 색을 살린 안이에요. 안 고르시면 1번으로 갈게요."
2. 사진이 아직 없으면 표지는 S05(동네형은 S07도 가능)로 한다. S01·S02 표지는 쓰지 않는다. 밝은 브랜드 색은 면(띠·박스·배경)으로만 쓰고, 강조 글자는 같은 계열 진한 색으로 한다(`guides/07-design-kit.md` 1)).
3. 고른 안을 브랜드 프로필 디자인 키트에 적고, 다음부터는 묻지 않는다. 답이 없으면 1안으로 저장한다.
4. **사진은 사장님 실제 사진이 먼저다.** 장마다 필요한 사진을 구체적으로 부탁한다: "내일 오픈 전 크루아상 단면 사진 2장, 위에서 찍은 것 1장".
5. AI 이미지 경계:
   - 금지: 실제 매장·메뉴·상품·사람처럼 보이는 AI 이미지, AI 인물 후기. 실제처럼 오해할 수 있으면 금지.
   - 허용: 누가 봐도 그림인 것(일러스트·아이콘·패턴 배경)을 장식용으로만.
   - AI로 만들거나 보정한 의료 전후사진은 금지. 실제 의료 전후사진도 기본값 '권하지 않음'(5조건+사전심의, `guides/compliance/medical.md`).
   - **한글 글자는 생성 모델에 맡기지 않는다**(글자가 깨진다). 글자는 렌더러가 그린다.
6. **사진은 문구와 맞아야 한다.** 장 문구가 "밤 크루아상 단면"인데 가진 사진이 일반 크루아상이면, 문구를 사진에 맞춰 바꾸지 않는다. 그 장을 '사진 필요'로 두고(`photo` 없이 `photo_hint`에 필요한 사진을 적는다. 비슷한 사진을 임시로 쓰면 `photo_match`에 다른 점을 적는다) 사장님께 맞는 사진을 부탁한다.
7. 원고를 보여 줄 때 **사진이 필요한 장을 표시한다**: "2장: 밤이 보이는 단면 사진 필요, 1장: 지금 사진은 일반 크루아상이라 확인 필요". 사진 스타일인데 사진이 없는 장은 렌더러가 글자 카드로 대신 그리고 '사진 필요'를 띄운다.

### 4) 원고 JSON 쓰기 → 렌더

칸 설명·시각 앵커 종류(number·icon·flow·vs·button·chips·table·timeline)는 **`guides/make/cardnews-spec.md`**를 연다. 견본: `examples/cardnews-spec-sample.json`(빵집 신메뉴, 사진 처리), `examples/cardnews-spec-faq-sample.json`(FAQ, 장마다 다른 앵커).

**스크립트 모드** (Pillow 있음). 도구는 `BASE + tools/cardnews.py`를 받아 쓴다:
```bash
python3 cardnews.py fonts                       # 처음 한 번: Pretendard 등 무료 폰트 받기
python3 cardnews.py check spec.json             # 원고만 점검(글자 수·장수·색 대비)
python3 cardnews.py render spec.json -o out/    # out/01.jpg… (업로드용) + 01.png… + check.json
```
- 폰트는 Pretendard·나눔손글씨 펜·고운바탕(모두 SIL OFL)을 공식 저장소에서 받는다. 받기에 실패하면 시스템 한글 폰트로 그리고 점검 결과에 "폰트" 주의가 뜬다.
- **같은 브랜드 팔레트**: `brand.colors`는 프로필 '우리 가게 색' 값을 그대로 넣는다(렌더러 기본 색으로 내지 않는다). 같은 소재 숏폼은 이 값을 `colors`로, 표지 제목 글꼴을 `font`로 넘겨 맞춘다(변환은 `guides/make/shortform.md` 6) '같은 브랜드 팔레트'). 표지 01장과 숏폼 첫 장면을 나란히 놓고 색·글씨·훅 문구가 같은지 본 뒤 낸다.
- 표지 문구에는 이번 소재의 **지금 올 이유**(`guides/04-weekly.md` ③-1)를 넣는다. 원고 끝에 `빌린 것: 레퍼런스 A의 ○○(구조), B의 ○○(훅 틀)` 한 줄.

**Pillow가 없을 때 (사장님께 설치를 묻지 않는다. 위에서부터 차례로)**
1. 네가 명령을 실행할 수 있으면 `pip install pillow`(안 되면 `python3 -m pip install --user pillow`)를 한 번 시도한다. 되면 위 스크립트 모드.
2. 안 되면 `python3 cardnews.py render spec.json -o out/ --html`로 HTML을 만들어 네 브라우저로 캡처한다.
   - `out/cardnews.html`을 네 브라우저로 연다(창 너비 1080px 이상).
   - `#card01`, `#card02` … 요소를 하나씩 캡처해 `01.jpg`…로 저장한다. 요소 캡처가 안 되면 화면 캡처 후 1080×1350으로 자른다.
   - 이 경로는 사진 위 글자 대비를 자동으로 못 잰다. 6)의 표대로 눈으로 확인한다.
3. 브라우저도 없으면 장별 원고 + 디자인 지시(색 헥스 값, 글자 크기, 사진 위치)를 표로 주고, 사장님이 미리캔버스나 캔바에서 만들도록 안내한다.
   > "제가 지금 있는 곳에서는 그림 파일을 바로 못 만들어요. 장마다 넣을 글과 색을 정리해 드릴게요. 미리캔버스(무료)에서 '카드뉴스' 틀을 고르고 그대로 옮겨 주시면 돼요."

### 5) 자동 점검 읽기

렌더 끝에 `[고칠 것]`·`[주의]`가 나온다. **고칠 것이 0이 될 때까지** 고쳐서 다시 렌더한다.

| 항목 | 기준 | 걸리면 |
|---|---|---|
| 대비 | 본문 **4.5:1**, 큰 제목(60px 이상) 3:1 | 글자색을 먹색/흰색으로, 사진이면 S02(아래 어둡게)로, 강조색은 면으로만 |
| 안전 영역 | 핵심 글자가 가운데 1080×1080(표지는 1012px 폭) 안 | 글을 줄인다. 사진 칸을 줄인다 |
| 넘침 | 최소 글자 크기로도 칸을 넘음 | 장을 나눈다 |
| 과밀 | 본문 120자 초과(160자 초과는 고칠 것), 글자를 줄여 맞춤 | 문장을 줄이거나 장을 나눈다 |
| 본문 40px 미만 | 칸에 맞추려고 본문이 40px 아래로 줄어듦 | 문장을 줄이거나 장을 나눈다 |
| 빈 공간 과다 | 글·사진이 장 세로의 40% 미만만 채움 | 항목·사진을 더하거나(`menu`·`compare`·`steps`) 장을 합친다 |
| 콘텐츠 높이 | 내용이 세로 60% 미만(목표 70~80%) | 앵커(숫자·표·카드)를 키우거나 `bar`·항목을 더한다 |
| 시각 앵커 | 숫자·사진·도식이 없어 아이콘을 자동으로 넣음 | 그 장의 숫자·예로 `anchor`를 지정한다 |
| 같은 바탕 | 같은 바탕색 3장 연속 | `tone`을 brand·deep으로 섞는다 |
| 같은 레이아웃 | 같은 틀 2장 연속(주의), 3장 이상(고칠 것) | 앵커 종류나 바탕을 바꾼다 |
| 사진 필요 | 사진 스타일인데 실제 사진이 없어 글자 카드로 그림 | 사장님께 그 장 사진을 부탁한다(문구는 그대로) |
| photo_match 확인 필요 | 사진이 문구와 다르다고 적힌 장 | 맞는 사진을 받기 전에는 올리지 않거나 사진을 뺀다 |
| 빈칸 | `[직접 입력: …]`이 남음(**고칠 것**) | 사장님 자료로 채운다 |
| 표지 제목 | 12~19자 | 줄이거나 늘린다 |
| 장수·마지막 장 | 10장 이하, 마지막 장 `cta` | 합치기, 마지막 '할 일' 장 더하기 |
| 용량 | JPEG 8MB 이하 | 사진 해상도를 줄인다 |

### 6) 눈으로 확인 (꼭 이미지를 직접 열어 본다)

1. 렌더한 이미지를 **실제로 열어서** 본다. 점검 통과만 믿지 않는다. 고칠 것이 있으면 원고를 고쳐 다시 렌더한다. **최소 한 번은 다시 보고 고친다.**
2. 확인할 것: 글자 잘림·겹침, 한 줄에 한두 글자만 남은 줄, 얼굴·제품 위 글자, 강조가 3곳 이상, 장마다 위치가 들쭉날쭉한 제목.

### 7) 플랫폼별 캡션

같은 이미지에 캡션은 플랫폼마다 따로 쓴다(자세한 것: `guides/make/repurpose.md`).

| 플랫폼 | 캡션 |
|---|---|
