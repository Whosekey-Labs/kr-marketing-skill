# 0. 시작: 상황 파악 + 모드 (처음 한 번)

목표: 사장님 상황을 5갈래 중 하나로 나누고, 갈래에 맞는 경로로 1단계(조사)에 들어간다. **상황은 따로 묻지 않고 조사로 추정한 뒤 1단계 확인 메시지에서 한 줄로 확인한다**(질문 수를 줄이기 위해).

## 1) 상황 판별 (조사로 추정 → 확인 메시지에서 확인)

첫인사에서 상호·지역(또는 링크)을 받으면 바로 조사(`guides/01-research.md`)를 시작한다. 조사 결과로 아래 표에서 갈래를 고른다.

| 갈래 | 조사에서 보이는 신호 |
|---|---|
| ① 완전 처음 | 플레이스가 없거나 거의 비어 있음, 블로그·인스타 없음 |
| ② 이미 운영 중 | 블로그나 인스타에 최근 30일 안 게시가 꾸준함 |
| ③ 일부 채널만 / 대행사에서 넘어옴 | 채널을 쉬고 있음(마지막 게시 3달 이상 전), 한 시기에 협찬 글이 몰려 있음 |
| ④ 오픈 준비 | 플레이스 없음 + 사장님이 "오픈 전"이라고 말함 |
| ⑤ 매장 없는 사업 | 손님이 찾아오는 매장이 없음: B2B·소프트웨어·온라인 판매·외주·1인 브랜드. 홈페이지·크몽 같은 플랫폼 상품 페이지·스마트스토어가 중심 |

- 확인 메시지에 **번호 선택지**로 넣는다(문구는 `guides/01-research.md` '확인 메시지'). 추정한 번호를 "(저는 2번으로 봤어요)"처럼 같이 적는다. 가게를 못 찾았으면 상황 번호에 더해 **등록 상태를 가·나·다**로 묻는다(숫자 번호는 한 메시지에 한 묶음만 — "3번"은 늘 상황 3이다). 중간부터 요청이면 등록 상태를 먼저 묻지 않는다(SKILL.md).
- 갈래를 사장님께 말할 때 "멈춤·방치·실패" 같은 말을 쓰지 않는다. ③은 "채널을 잠시 쉬고 계신 상태", ④는 "오픈 준비 중"이다.
- 갈래 ④는 '메뉴·리뷰'가 없다. 조사·질문의 '메뉴'를 **준비 중인 상품·가격**으로 바꿔 읽는다(`guides/02-interview.md` 라운드 1의 '갈래 ④').
- 업종 파일이 07·23·24·25(방문하지 않는 업종)면 ⑤로 본다.
- 답을 기억에 저장한다(`상황: ①~⑤`). 다음 대화에서는 다시 확인하지 않는다. 업종 파일의 "개업 단계" 질문도 이 답을 쓰고 다시 묻지 않는다.

## 2) 갈래별 경로

| 갈래 | 1단계 조사에서 더 볼 것 | 2단계 질문에서 바뀌는 것 | 첫 결과(이번 주 고칠 3가지)로 노릴 것 |
|---|---|---|---|
| ① 완전 처음 | 경쟁 3~5곳 조사에 비중. 플레이스 등록 여부부터 | 없음 | 플레이스 등록·빈칸 채우기 |
| ② 이미 운영 중 | 기존 글 최근 10편의 말투와 잘된 글 3편(01-research 7)) | 없음 | 잘되는 채널은 유지·강화, 플레이스 빈칸 정비 |
| ③ 일부 채널만 / 대행사 | 채널별 마지막 게시일, 대행사 시절 글(협찬 표시 여부), 갑자기 줄어든 리뷰·노출 | 갈래 질문 1개(02-interview '갈래·업종 질문') | 쉬고 있는 채널 1개 다시 시작 + 위험 이력 정리 |
| ④ 오픈 준비 | 같은 상권 경쟁 3~5곳, 오픈 시기 시즌 | 라운드 1의 1)·4)를 오픈 목표·준비 중인 상품·가격으로, 갈래 질문 1개(촬영 가능한 곳). 업종 필수 사실(요금·환불 등)은 질문 수 밖 | 플레이스 등록·사진 몰아 받기·가격표 확정 → 오픈 D-14부터 예열 |
| ⑤ 매장 없는 사업 | 플레이스 대신 홈페이지·플랫폼 상품 페이지·문의 경로(01-research 1-1)) | 라운드 1을 문의·계약 숫자로 바꿈(02-interview) | 홈페이지·상품 페이지·문의 경로 고칠 3가지 |

갈래별 주의:
- ③에서 리워드 트래픽·리뷰 대행·좋아요 구매를 썼다면, 비난하지 말고 알린다: "이제부터는 멈추는 게 안전해요. 네이버는 대행·리워드로 쓴 리뷰가 한 번만 확인돼도 가게 리뷰 전체를 안 보이게 할 수 있다고 공지했어요(네이버 공지, 2026-01)." 병의원이면 "환자 후기·체험 글은 광고 표시를 해도 의료법상 쓸 수 없는 치료경험담일 수 있어요(보건복지부 의료광고 가이드라인). 대가를 준 경우 환자 유인에 해당하는지는 사안마다 달라요"를 더하고, 판단은 `guides/compliance/medical.md`를 따른다. 지난 리뷰 이벤트(영수증 리뷰 → 무료 혜택 등)를 사장님이 말하면 `guides/08-operations.md` 7) '지난 이벤트 정리'대로 한다.
- ①·④는 비교할 숫자가 없다. 첫 달 목표를 **"지금 숫자 재 두기"**(지침상 기준값 만들기)로 둔다. 첫 달은 실험하지 않는다(`guides/03-strategy.md` 9)).
- ⑤는 플레이스·지역 순위·처음/단골·프랜차이즈 질문을 하지 않는다. 경쟁은 검색어와 플랫폼(크몽 등) 기준으로 본다.
- 어느 갈래든 업종 확인(규제 플래그)은 건너뛰지 않는다(`guides/01-research.md` 6)).

## 3) 역할 안내 (첫 결과를 보낼 때 한 번, 짧게)

'이번 주 먼저 고칠 3가지'를 보낼 때 아래를 덧붙인다. 사장님 시간이 얼마나 드는지 먼저 알려야 기대치가 맞는다.

```
앞으로 이렇게 할게요.
- 제가 하는 것: 가게 조사, 계획, 글·카드뉴스·짧은 영상 만들기, 광고 규칙 점검, (원하시면) 올리기, 결과 정리
- 사장님이 하실 것: 일주일에 사진 몇 장·짧은 확인, 로그인·보안문자 입력
- 사장님 시간은 주 1~2시간 안쪽으로 맞출게요.
- 성과는 보통 2~3달은 봐야 해요. 오늘 보낸 3가지처럼 바로 보이는 것부터 할게요.
```

## 4) 연결은 필요할 때 하나씩

지금은 아무것도 연결하라고 하지 않는다.

| 연결 | 언제 | 어디서 |
|---|---|---|
| 구글 문서·드라이브 | 브랜드 프로필을 저장할 때 | `guides/03-strategy.md` 11) |
| 네이버·인스타·유튜브 등 SNS 계정 | 첫 업로드 직전 | `guides/upload/index.md` |
| 깃헙 (선택) | 제보할 때 | `guides/feedback.md` |

- 연결 방법은 네 앱 화면 기준으로 짧게 안내한다(예: 피클은 앱 연결, Claude는 설정 → 커넥터, ChatGPT는 설정 → 앱). 메뉴 이름이 다르면 네 앱 기준으로 고쳐 말한다.
- 비밀번호는 채팅으로 받지 않는다. 네 앱의 로그인·금고 기능으로만 연결한다.
- 거절하면 기억하고 다시 묻지 않는다.

## 5) 모드 확인 (말하지 않고)

SKILL.md 0-2에서 정한 모드를 쓴다. 아직 안 정했으면 지금 정한다.

| 모드 | 조건 | 조사 방법 |
|---|---|---|
| 스크립트 모드 | `python3 mk.py check`가 성공 | 네이버 개발자 키가 있으면 `mk.py place`·`search-blog`·`rank`(공식 API), `blog-list`(RSS). 키가 없으면 링크·캡처 + 브라우저(`guides/01-research.md` 공통 규칙) |
| 브라우저 모드 | 파이썬 실행 불가·네트워크 오류 | 네가 쓸 수 있는 브라우저로 `guides/01-research.md`의 주소를 연다 |

- 스크립트 명령이 하나만 실패하면 그 항목만 브라우저로 한다. 모드를 통째로 바꾸지 않는다.

### 5-1) 네이버 열쇠(공식 키) — 처음 설정 때 권장

네이버 약관은 허락 없는 자동 검색을 양과 상관없이 금지한다(`ax/research/marketing-skill/10b` 4장). 공식 키가 있으면 조사·주제 찾기를 약관 걱정 없이 스크립트로 한다.

| 키 (환경변수) | 주는 것 | 발급 |
|---|---|---|
| 네이버 개발자 `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET` | 검색 API(블로그·지식iN·지역, 하루 25,000회), 데이터랩 검색어트렌드(하루 1,000회) | developers.naver.com → Application 등록 → 검색·데이터랩 선택 → WEB 주소 `http://localhost` |
| 검색광고 `NAVER_AD_API_KEY`·`NAVER_AD_SECRET`·`NAVER_AD_CUSTOMER_ID` | 월간 검색수(PC·모바일)·연관 키워드. '경쟁'은 광고주 경쟁이다 | searchad.naver.com **광고주 가입이 먼저**(약관·사업자 정보 입력, 사장님 확인 필요) → 도구 → API 사용 관리 |

- 시간: 네이버 개발자 키는 로그인 뒤 3~5분. 검색광고 키는 광고주 계정이 없으면 가입부터라 더 걸린다(이미 있으면 5분 안팎).
- 사장님은 **로그인(검색광고는 가입 정보 확인까지)만** 네 브라우저에서 직접 한다(비밀번호를 받지 않는다). 나머지 입력·복사는 에이전트가. 약관 동의 화면은 사장님께 보여 주고 확인받는다. 키는 환경변수·비밀 저장소에만 두고 프로필·채팅에 적지 않는다. 공식 문서에 한도는 있으나 '무료' 문구는 없다.
- 키 경로는 실제 키로 아직 시험하지 않았다(2026-11-17). 받으면 `python3 mk.py check`로 먼저 확인한다.
- 사장님께: "네이버 검색을 제가 대신 보려면 네이버 열쇠가 필요해요. 로그인만 해 주시면 나머지는 제가 할게요. 안 하셔도 일은 돼요. 그땐 가게 링크나 화면 캡처를 보내 주시면 돼요."
- 거절하면 기억하고 다시 묻지 않는다. 묻는 순서: **키 먼저** → 키를 거절했고 네이버 자료가 꼭 필요할 때만 `--unofficial` 동의를 묻는다(`guides/09-discovery.md` 2)). 두 답 모두 프로필 '사장님과 정한 것'에 저장하고 매주 다시 묻지 않는다.

## 6) 기억할 것

- 상황 갈래(①~⑤), 상호·지역(또는 링크), 오픈 예정일(④)
- 연결된 것·거절한 것, 모드, 예약 실행을 걸었는지
- 다음 대화에서는 이 단계를 건너뛰고 기억한 단계부터 잇는다(먼저 밀린 일 점검, `guides/04-weekly.md` ⓪).
