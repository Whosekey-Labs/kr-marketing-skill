# 이번 주 주제 찾기

- 원문 주소 앞부분(BASE): `https://raw.githubusercontent.com/Whosekey-Labs/kr-marketing-skill/main/`
- 본문 지침: `BASE + guides/09-discovery.md`를 열어 그대로 따른다.
- 도구: `BASE + tools/mk.py`를 받아 `python3 mk.py check`. `season`·`ideas`·`trend`·`festival`을 쓴다. 네이버는 공식 API 키(`NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET`, 검색광고 `NAVER_AD_*`)가 있을 때만 자동으로 본다. 없으면 구글·유튜브 자동완성, 내장 달력, 축제, 사장님 말로 한다.
- 고른 주제로 만들 때: 전체 스킬 `BASE + SKILL.md`의 4단계(`guides/04-weekly.md` ②부터).

## 꼭 지킬 것 (지침을 못 열어도)
1. 순서: 시즌(`season` 기본 8주, 상권·관광지면 `festival`) → 검색 수요(업종이 '켬'이거나 '약하게'인데 블로그 후보가 필요할 때만 `ideas -k "동네 업종" --wide 시구 --menu 대표메뉴`) → 사장님 3문항(이번 주 새로 생긴 것 / 손님이 묻거나 한 말 / 지난주 반응 좋았던 것) → 관문 → 점수 → 상위 3개 + 채널.
2. **네이버 약관**: 허락 없는 자동 검색은 양과 상관없이 금지. 공식 API(키)를 먼저 쓰고, 키 발급은 사장님이 로그인만 하고 나머지는 에이전트가. 네이버 검색 화면 자동 읽기(`--unofficial`)는 사장님 동의 뒤 이 가게 1곳 몫만, 주 1회. 여러 가게 몫을 서버에서 모아 부르지 않는다. 네 브라우저로 네이버에 검색어를 넣는 것도 같은 동의가 필요하다. 사장님이 준 특정 주소(플레이스·블로그 글)만 열어도 된다. 동의는 키를 거절했을 때 한 번만 묻고 프로필에 저장한다.
3. 검색 데이터는 업종별로: 비교·예약형(미용·학원·병원·정비·숙박)은 시·구 단위로 켜고, 동네 생활형(반찬·분식·세탁·편의)은 끈다. 검색 도구는 블로그 주제에만, 당근·인스타는 손님 말·가게 소식에서.
4. 관문(무관 / 시기 지남 / 이번 주 못 만듦 → 탈락) 뒤 점수 15점 = 목표 연결×2 + 시기(채널별: 블로그 4~8주 뒤, 당근·인스타 이번 주가 최고) + 손님 언어(우리 손님 말 > 동네 검색 > 전국) + 만들기 쉬움. 키워드도구 '경쟁'은 광고주 경쟁이라 쓰지 않는다.
5. 다가올 시즌은 쇼핑인사이트 '작년 같은 시기 2~6주 뒤'에서. 이번 주 순위는 이미 지난 결과.
6. 3개는 질문형·시즌형·가게 소식형을 섞는다. 근거는 실제로 수집한 것만 한 줄씩. 수치·손님 말을 지어내지 않는다. 못 가져온 소스는 "이번 주 못 가져왔어요" 한 줄.
7. 결과는 프로필 '주제 후보 장부'에(주, 후보, 유형, 점수, 근거 데이터·날짜, 채널, 상태, 반응). 지난 4주와 같은 주제는 뺀다.
8. 병원·학원·건강 주제는 그 업종 광고 규칙(`guides/compliance/`)부터. 사장님께는 쉬운 말로.
